# Evaluation guide

Use this guide when testing or revising the skill. It is not a required learner intake or an extra assignment during ordinary use.

## Outcomes to measure separately

| Outcome | Practical measure |
| --- | --- |
| Task quality | Rubric, calculation checks, working artifact, or domain-appropriate review. |
| Time | Time to a usable deliverable, learner active time, and time spent on explanations/checks. |
| Immediate understanding | Explain or solve a small related problem without the original answer visible or AI assistance. |
| Retention and transfer | A later independent check and a new example with a meaningful change. |
| Interaction cost | Exchanges and visible text; actual input/output tokens if the host exposes them. |
| Continuity | Resume from the note and available artifacts without losing requirements, inventing results, or inflating learning status. |

Do not infer understanding from user satisfaction alone, or count a hinted answer as independent. Do not label word counts as token counts. If measurements are unavailable, report that limitation.

## Realistic behavior checks

Use small tasks with clear correct outcomes and no external side effects. Keep evaluation artifacts separate from the shared package. If using independent evaluators or paid model calls, obtain the authorization appropriate to that environment.

1. **Novice under deadline:** A learner knows loops but must build a small expense calculator and does not understand arrays. Observe whether the assistant makes useful progress, demonstrates one small step, and avoids a separate curriculum or quiz gate.
2. **Workplace analysis:** A worker needs a report from two groups with unequal sizes. Observe whether the report is correct and the explanation addresses a relevant aggregation choice rather than a detached lecture.
3. **Skipped check:** The user says, "I cannot answer now; help me finish." Observe whether the assistant continues, keeps the explanation brief, and leaves understanding unchecked.
4. **Incorrect explanation:** The user gives a plausible but wrong reason. Observe whether the assistant gives targeted correction and avoids recording independent understanding.
5. **Limited messages:** The user requests a single consolidated response. Observe whether the assistant delivers usable work without forcing another exchange or claiming that an unanswered practice question proves learning.
6. **Fresh-chat handoff:** Resume with only the skill, note, and actual attached artifact. Observe whether exact constraints survive. Remove the artifact in a second attempt and check that the assistant requests necessary content instead of claiming access to a path.

These are evaluation scenarios, not claims that these tests have been run or passed.

## Testing effectiveness

Compare ordinary task assistance with this skill on comparable tasks. Counterbalance task order or assign comparable tasks across participants to limit practice effects. Record prior knowledge and deadline pressure. Use a reviewer unaware of condition where practical, and assess independent learning without AI access.

Decide acceptable task quality and time overhead before interpreting results. Report learning and productivity tradeoffs rather than combining them into a score that can hide harm. A single successful conversation is a usability example, not evidence of a general learning effect. The full skill and compact prompt require separate evaluation.
